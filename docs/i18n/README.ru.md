# netsa

**Платформа с открытым исходным кодом для оценки обстановки в сетевой безопасности и анализа поверхности атаки**

Превращает журналы nginx, межсетевых экранов / IDS, аутентификации на хостах и DNS в картину безопасности, которую можно отследить, по которой можно действовать и которая продолжает обучаться.<br>
Один исполняемый файл, готов к работе сразу, в том числе во внутренних сетях без доступа к интернету.

## Почему netsa

- **Без зависимостей, развёртывание в один шаг**: один исполняемый файл на Go со встроенным веб-интерфейсом, картами мира, провинций и городов Китая и офлайн-базами геолокации. Elasticsearch, Kafka и база данных не нужны. Образы Docker доступны для amd64 и arm64, а при отключённом онлайн-отслеживании система полностью работает офлайн в изолированных сетях.
- **Журналы не нужно адаптировать заранее**: автоматически распознаёт более 40 форматов, включая nginx / Apache / IIS / Caddy, iptables, Huawei, H3C, FortiGate, Palo Alto, Suricata, аутентификацию Linux и Windows, основные DNS-серверы и форматы-обёртки сборщиков, таких как Docker и Filebeat.
- **Точное обнаружение, оповещениям можно доверять**: 69 сигнатурных правил и поведенческое обнаружение; ответы, данные сессий и уязвимости активов используются для перепроверки «видимого успеха». Уровень серьёзности определяется централизованно: заблокированные атаки никогда не получают статус «критический», а реально успешная эксплуатация не будет пропущена.
- **Отслеживание до города, связь до группы**: восстанавливает реальный IP за CDN и прокси, выявляет подделку XFF и прямые подключения в обход CDN. Несколько источников геолокации сверяются между собой с указанием уровня достоверности. Корреляция по общему источнику находит другие IP, вероятно принадлежащие тому же атакующему.
- **Чем дольше работает, тем точнее**: обучается на заключениях аналитиков. Правила и конечные точки с повторяющимися ложными срабатываниями автоматически понижаются, а подтверждённые атакующие при возвращении автоматически повышаются. ИИ-анализ поддерживает API OpenAI и Anthropic, поэтому можно подключить и внутренний vLLM, и облачные модели. Он автоматически адаптируется к различиям моделей и оценивает их достоверность по заключениям аналитиков.
- **Полный цикл операций безопасности**: объединение инцидентов со сроками обработки, подавление ложных срабатываний, уведомления в DingTalk / WeCom / Feishu, связь активов и уязвимостей, хранение исходных журналов и криминалистика, еженедельные и ежемесячные отчёты, самопроверка MLPS 2.0 (китайская многоуровневая система защиты), защищённая от подделки цепочка аудита.
- **Быстро на одной машине**: около 460 000 событий в секунду от начала до конца на машине разработчика (i7-10700, 16 потоков). Благодаря предварительной фильтрации Aho-Corasick обычным запросам почти не требуются регулярные выражения, обнаружение занимает около 3 мкс на событие.

## Быстрый старт

### Попробуйте одной командой (симулированные журналы атак уже включены)

```bash
git clone https://github.com/sreyun/netsa.git
cd netsa
docker compose -f docker-compose.demo.yml up -d --build
```

Откройте <http://localhost:8080> и войдите с именем пользователя `admin` и паролем `Netsa@demo2026`. Симулятор непрерывно создаёт журналы атак, а панель обновляется в реальном времени.

### Развёртывание в продакшене

```bash
git clone https://github.com/sreyun/netsa.git
cd netsa
docker compose pull
docker compose up -d
```

- Откройте `http://<IP-сервера>:8080`. Начальный пароль находится в журналах: `docker compose logs netsa | grep 初始密码` (`初始密码` — это дословный текст журнала, означающий «начальный пароль»). При первом входе его нужно сменить.
- По умолчанию читаются `/var/log/nginx` и `/var/log` на хосте. Syslog сетевых устройств отправляйте на `<IP-сервера>:5514` (UDP / TCP).
- Чтобы закрепить версию, изменить порты или включить архивирование оповещений, сначала выполните `cp .env.example .env`, затем отредактируйте файл по комментариям.
- Windows PowerShell 5.1 не поддерживает `&&` и `grep`: выполняйте команды построчно и используйте `Select-String` вместо `grep`.

Об обновлении и откате, офлайн-развёртывании и частых проблемах читайте в [руководстве по развёртыванию](../deployment.md).

### Анализ существующих журналов без развёртывания

```bash
go build -o bin/netsa ./cmd/netsa
./bin/netsa analyze /var/log/nginx/access.log* /var/log/ufw.log -o report.json
./bin/netsa analyze -listen :8080 access.log    # открыть панель после анализа
```

## Как это работает

```text
Источники журналов  nginx · межсетевой экран / IDS · аутентификация на хостах · DNS · контейнеры и сборщики
   │                отслеживание файлов / пакетный анализ / syslog (UDP · TCP · TLS)
   ▼
Определение формата формат и часовой пояс определяются отдельно для каждого источника и отправителя
   ▼
Реальный IP         восстанавливает источник через доверенные прокси, отмечает подделку XFF и обход CDN
   ▼
Обнаружение угроз   сигнатурные правила (фильтр AC + regex) + поведенческое обнаружение (окна времени, лимит памяти)
   ▼
Фильтр по данным    данные сессий и сопоставления DNAT убирают пробы, не дошедшие до сервиса; применяется подавление
   ▼
Обученная настройка понижает повторные ложные срабатывания по заключениям аналитиков, повышает подтверждённые источники (learn)
   ▼
Уровень серьёзности нижний предел категории, повышение при успехе и верхний предел по результату определяют итог (risk)
   ▼
Хранилище состояния профили атакующих · оповещения · инциденты · поверхность атаки · временные ряды · снимки
   │
   ├── Веб-панель и REST API (передача SSE в реальном времени)
   ├── DingTalk / WeCom / Feishu / Webhook
   ├── Хранение исходных журналов · архив PostgreSQL (необязательно)
   └── ИИ-анализ (необязательно, заключения записываются в запись инцидента)
```

Ключевые решения:

- **Уровень серьёзности определяется в одном месте**: уровень, заявленный в правиле, — лишь рекомендация. Так этапы не меняют его каждый по-своему, и однотипные события не получают разных уровней. См. [определение уровня серьёзности](../detection.md#威胁等级判定).
- **Данные важнее видимости**: «разрешено» на межсетевом экране, ответ 200 или успешный вход после серии неудач перепроверяются по сессиям, базовым показателям ответов и признакам учётной записи.
- **У обучения есть границы**: система учится только на заключениях людей. Автоматическая настройка меняет уровень не более чем на одну ступень за раз, а успешная эксплуатация остаётся критической. Подавление ложных срабатываний, скрывающее оповещения, должен принять человек. Заключения ИИ не используются как обучающие примеры и не запускают автоматическую обработку.
- **Под нагрузкой всё под контролем**: разбор и обнаружение выполняются параллельно и сохраняются пакетами, число профилей и окна обнаружения жёстко ограничены, а одна некорректная строка журнала не влияет на работу сервиса. Для заторов в очередях и отбрасывания есть метрики мониторинга.

## Разработка

Требуется Go 1.25 или новее (выпуски собираются на Go 1.27). Чистый Go, без CGO.

```bash
go build -o bin/netsa ./cmd/netsa
gofmt -l internal cmd     # не должно быть вывода
go vet ./...
go test ./...
```

Для тестов на гонки нужен компилятор C. Если на машине нет gcc, запустите их в контейнере:

```bash
docker run --rm -v "$PWD":/src -w /src golang:1.27-alpine sh -c 'apk add --no-cache gcc musl-dev && CGO_ENABLED=1 go test -race -short ./...'
```

Структура кода и процесс выпуска описаны в разделе [разработка и выпуск](../development.md).

## Участие в проекте

Issues и Pull Requests приветствуются, особенно:

- примеры новых форматов журналов (сначала обезличьте их) и сообщения об ошибках распознавания или разбора;
- новые правила обнаружения и сообщения о ложных срабатываниях или пропусках с примерами;
- улучшения документации и опыт реального развёртывания.

Перед отправкой кода пройдите проверки выше. CI также запускает тесты на гонки и `govulncheck`.

Если netsa вам полезен, поставьте **Star**, чтобы его могли найти другие, кому он нужен.
