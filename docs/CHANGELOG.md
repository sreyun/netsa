## 1.11.8

继续处理上一轮复查中余下的问题，并补查此前未覆盖的子系统。

### 检测

- **远程文件包含的“本站”豁免被绕过**：豁免依据的是客户端提供的 Host 头，把 Host 改成攻击者的域名即可让告警消失；带账号信息的地址（`本站:x@evil.com`）、前一个参数指向本站而后一个指向别处、末两段相同的另一个 IP 也都被当成本站。现在只有已登记的资产、或首页有稳定正常访问的站点才豁免，并且每个参数都要指向本站。
- **HTML 实体还原破坏参数边界**：查询串里的 `&notify_url=`、`&param=`、`&region=` 被还原成 `¬ify_url=`、`¶m=`、`®ion=`，按参数匹配的内网地址 SSRF 规则因此漏报。现在只还原以分号结尾的实体与数字引用。
- **一条时间错误的日志引发持续的 DDoS 误报**：突增基线被衰减到接近 0 且被标为已成熟，繁忙服务之后每个窗口都被判为 DDoS，且不会自愈。现在时间明显在未来的日志不推动窗口，个别时间倒退的日志计入当前窗口，连续回放才重开窗口且保留基线；外发统计的滑动窗口同样不被未来时间锚定。
- **语法分析被截断时给出否定结论**：在载荷前面塞 32 个无关参数，真实的 SQL 注入被记为“语法分析判定不构成注入”，自学习据此降为低危。现在有参数没有分析到时只记为“未分析”。
- **请求体检测误报**：普通的大表单、4 KB 的正文被报成“超长URL”“超多参数绕过WAF”。请求体检测不再做描述请求行的检查。
- **不可能的旅行误报**：国家、省份的中心点被当成登录地点，同一国家内换个网络就被判为“飞了两千公里”。现在只比较定位到城市的地点。
- 横向登录链在两台主机互相登录时无限增长（跳数虚高、路径越来越长），现在识别环并限制长度；周期性外连的“已有 N 台主机”按不同主机计数（同一台主机隔天再次触发不再被说成第 N 台，真实的心跳不再被降为低危）；内网主机连接 IPv6 内网地址不再被报成连接公网；内网大范围端口扫描（阈值的 5 倍）可以升为高危；WebShell 跟踪表被字典扫描占满后会腾出无效条目。
- 第三方告警（Wazuh 等）的规则编号与名称来自日志原文，现在编号只接受短的字母数字、名称转义截断；状态库的规则统计表最多 4096 个不同编号，不再随伪造的告警无上限增长。

### 接口与运维

- **反向代理改写 Host 时无法登录**：跨站请求检查先比较 Origin 与 Host，放在 nginx 默认的 `proxy_pass` 之后时包括登录在内的所有写请求都被拒绝。现在以浏览器的 `Sec-Fetch-Site` 为准。
- **历史告警导出中途失败时返回完整外观的 CSV**：现在中断下载，不再让人把不完整的数据当作完整数据。
- **删除告警机器人时配置保存失败被当作成功**：现在提示“已删除，但保存失败，重启后会恢复”。
- **告警归档写入失败的通知漏发**：一小时内第二次故障永远不再通知，恢复时也没有通知，现在补发。
- **平台安全异常误报**：内置账号 admin 的常规操作、名称里含 admin 的令牌被报成“新增管理员 / 创建管理员令牌”，现在只看角色；账号登录网段满 50 个后之后的常用网段每次都报“从新地址登录”，现在淘汰最少使用的网段。

### 状态库与自学习

- 把 Host 换成 OAST 子域名的请求不再绕过兜底页面复核（站点键与攻击面登记一致）；攻击活动归并不再把同一 IPv6 /16 下不同主机的扫描当成“扫描同一主机”。
- 只撤销模型下调的人工操作同样写入处置记录日志；用户名以 AI 开头的分析员写过备注的事件不被自动归档；观察规则的轮询计数表满了之后会清掉过期的来源。

## 1.11.7

本版来自一次全面复查与生产环境核对，修复以下问题。

### 安全

- **开启 `require_2fa` 后新账号无法使用**：带初始密码（或刚被重置密码）的账号同时被要求改密与绑定身份验证器，两道检查互相拦住对方唯一的出口，除了查看会话与退出什么都做不了。现在先改密、再绑定。
- **API 令牌可以换成完整权限的登录会话**：用只读令牌调用绑定身份验证器的接口，会拿到所属账号完整权限的会话 Cookie。现在修改密码、绑定与关闭双因素认证只能在登录页面登录后操作，令牌与 HTTP Basic 认证一律拒绝。
- **HTTP Basic 绕过 `require_2fa`**：没有绑定身份验证器的账号第一次请求被拦住，之后 5 分钟内的请求命中缓存后放行。现在每次都按同样的要求判断；账号改过密码后缓存同时失效。
- **来源白名单可被伪造的 X-Forwarded-For 绕过**：可信代理把自己的值另起一行追加时（如 HAProxy），只读取了客户端自己写的第一行。现在合并全部行再从右往左取。
- **封禁列表导出**：写错的 `level`（如 `hihg`）被当成“全部”导出，原始参数还会写进生成的脚本（带换行时可插入命令）。现在写错返回 400，脚本中只出现规范的等级名。
- **原始日志检索的翻页不留审计**：自带一个任意的翻页位置就等于一次完整检索。现在翻页同样记入审计（“检索原始日志（翻页）”）。

### 检测

- **几种检测绕过**：方法名不标准（超长、小写、带数字）的请求整行被当成“非 HTTP 探测”，全部规则跳过；放在两个参数 `/*` 与 `*/` 之间的载荷对全部规则不可见；SQL 注入载荷末尾追加 `<svg>`、`alert()` 就被当成普通文字降为低危。现在都按完整规则检测，注释中检出的命中证据标明“（注释中）”。
- **漏洞接口签名的平方级开销**：同一段重复几百次的 8 KB 请求单条约 0.4 秒，可拖垮检测流水线。现在每个签名对一条路径只判断一次。
- **rundll32、regsvr32 的检测从未生效**：进程名去版本号时把末尾的 32 当成版本号去掉了。
- **WebShell 误判为“有证据”**：新上线的后台页面（路径含 upload、file）的第一次 POST 被当成“此前的上传”，管理员被定为严重并自动确认为攻击源。
- **行为检测**：表满后每条事件都在锁内全量清理（吞吐下降几个数量级），现在限速；一个时钟偏快的日志源会让其他日志源的统计窗口不断被清空，现在清理时间不超过系统时间；东西向横向移动的来源状态满 5 万后新来源永久不检测，现在清理 7 天没有管理连接的来源、满了淘汰最旧的。
- **节流吞掉升级的命中**：同一规则 10 分钟内已告警 5 次后，有证据的成功利用只记为命中、不生成告警，事件等级也不升。现在等级更高、第一次成功、第一次有证据的命中不受节流。
- **暴力破解成功被撤销**：登录接口的正常响应基线把攻击者真的登录成功判为“未成功”。现在只对能由响应判断成败的分类做基线复核。
- 华为防火墙“收到 IPSec 加密报文，未找到 Inbound SA”的日志此前计为解析失败（生产环境数万条），现在解析为被设备丢弃的连接。

### 自学习

- **由模型误判引发的误报连锁**（生产环境实际发生）：模型把员工出口的 3 个地址判为攻击，未知攻击发现据此把业务心跳接口学成观察规则，命中四万多次后才被自动停用。现在未知攻击发现只认由客观依据确认、分布在不同网段的攻击源（模型的结论不作为学习样本）；停用的规则不会被重新学成；先被模型确认、之后出现客观证据的来源不再按站点常客撤销。
- **停用规则的命中仍留在统计里**：只有停用规则命中的来源仍算作攻击源（总览、地图、攻击源列表），总览的攻击次数、等级分布、研判结果与目标排行也包含这些命中。现在一并剔除，规则重新启用后恢复。
- **纠错回溯**：已关闭、被模型调整过的事件里的告警没有标记为已撤销；事件更早的告警被淘汰后，按剩下的告警重算会把高危事件下调或标为误报；启动时重放纠错会把分析员重新打开的事件再次关掉。均已修正。
- **自动归档关闭被模型下调过的高危事件**：现在按下调之前的等级判断，模型的结论不触发自动处置。

### 地图与归属地

- **地点标注与归属地不一致**：直辖市在地名库中是省级，归属北京、在线库坐标在上海或广州的地址保留了错误的坐标，“北京”的标注被拉到山东。现在省级同样校正。
- **同一地点被拆成几个标注**：数据源写法不同（“广东省 / 广州市”与“广东 / 广州市”，“北京市 / 北京”）时各成一点。现在按地名库归一后合并。
- **在线定位失败后不再重试**：失败或没有结果的地址只有等级再次提升才重试，大量境外攻击源停在国家中心。现在按间隔重试（10 分钟起，最长 6 小时）。
- **内部对外的飞线指向 DNS 服务器或本单位网站**：DNS 日志、访问日志的目的地址被当成外部目标。现在只取防火墙记录的主动连接的对端；外部目标在定位库更新后同样重新定位。

### 其他

- **AI 研判**：遇到每小时调用上限时已取出的事件被丢弃，现在放回队首；自动研判只看列表前 50 条，被研判过的事件占满后新事件不再研判，现在按等级与出现时间从全部待处理事件中选。
- **报告时间写成 `9:00` 时永远不发送**（日报、周报、月报），现在规范为 `09:00`。
- **接口响应缓存的内存上限**：只按键数限制时过期的大响应一直占着内存，现在总量不超过 64MB。新增指标 `netsa_response_cache_bytes`。
- **监控指标重复的序列**：两个同名的数据源（默认配置里 ssh 的两个候选路径）各输出一条完全相同的序列，现在合并；同一指标的样本集中输出。
- 数据源页面显示配置文件里的白名单开关，而不是在界面中开启后实际生效的状态。
- 越界的端口（解析错位、伪造的日志）不再进入端口统计；总览排行取前若干项时不再复制并排序整张表；快照先落盘再改名；ICMP 目标不再显示端口（如“2048/icmp”）；`analyze` 没有事件时不再输出 0000-12-31 的时间范围。

### 修复

- **地图退出全屏后高度异常**：全屏时图表按整屏尺寸绘制，退出后地图容器的高度按画布内容计算，停在全屏时的高度（约 1000 像素以上），同一行的左右两列（威胁指数、攻击类型分布、实时告警）随之被拉高。现在地图高度只由页面布局决定、不随画布内容撑高，退出全屏后恢复原来的尺寸；过渡结束后再调整一次尺寸。

- **飞线密度可调**：攻击源多时（上千个地点、几百个内部对外目标）全部画线会密成一片。地图标题栏增加飞线按钮，在三种模式间切换并保存在浏览器中：**重点**（默认）只为高危、严重的地点与攻击最多的地点画线（世界视图 150 个、中国视图 100 个、省级 80 个，内部对外 60 个，全屏时各增加一半）；**全部**为每个地点画线；**关闭**只显示地点。所有地点始终以点标注。

## 1.11.4

### 改进

- **攻击来源地图全屏查看**：地图标题栏增加全屏按钮，整块地图面板（视图切换、统计、图例、说明）进入全屏，保留当前缩放与平移，标注的地点数加倍；Esc 或再次点击退出。浏览器不支持或不允许全屏时（桌面客户端的内置浏览器、iframe 等）改为铺满窗口。从全屏地图打开攻击源详情、下钻列表时自动退出全屏。
- 地图的“重置视角”与“全屏”改为图标按钮，移到标题栏右侧、与世界 / 中国切换并排且高度一致，不再遮挡地图；全屏按钮在展开 / 收起两个图标间切换，悬停有提示。
- 地图下方的说明精简为短句（如“6 个攻击源无法定位 · 空心点为近似位置”），原因与改进办法放到悬停提示中；“内部对外”的含义放到图例的悬停提示中。

### 性能

- **防火墙日志处理提速约 1.5 倍**（生产环境 95% 以上的日志是华为防火墙会话日志）：键值对解析复用键值表、按原始写法缓存键名的归一结果；RFC3164 报文头改为手写的快速匹配（每条 2.2µs → 1.0µs，与原正则逐条对照一致，模糊测试约 90 万次无差异）；内网地址判断对 IPv4 按字节比较（每条日志要判断十几次）；行为检测不再为每条日志格式化统计窗口文字。每条日志的内存分配由 45 次、4.9KB 降到 19 次、2.2KB，垃圾回收压力随之下降。
- **攻击面接口**：2 万个入口、2 万个服务时，生成报告由约 87ms 降到 16ms、内存分配由 18MB 降到 0.4MB：只选出页面需要的前 500 个入口、300 个服务再复制，不再复制全部后整体排序（期间持有读锁、阻塞日志入库）。生产环境中这是唯一明显慢的接口（约 240ms）。
- **攻击源列表**：分页查询只保留前若干个候选，5 万攻击源取一页由约 82ms 降到 15~21ms、内存分配由 16MB 降到 25KB，结果与完整排序逐条一致。
- **攻击活动归并**：缓存过期后先返回上一次的结果、在后台重新归并（同一时间只有一个），攻击活动页面与全局搜索不再等待整轮归并（数千个攻击源约百毫秒以上）；归并时攻击源评分在读锁内取出，消除一处数据竞争。ATT&CK 矩阵改由增量统计生成（约 100ms → 0.1ms）。
- **页面加载**：前端静态文件按内容生成 ETag，没有变化时返回 304，不再每次打开都重新下载脚本、样式与页面（约 430KB）；压缩结果缓存，ECharts、世界地图等大文件只压缩一次（使用最高压缩率）。

## 1.11.3

### 改进

- **攻击来源地图的飞线贴合实际**：此前只有攻击最多的 60 个来源地点有飞线（动画开销的限制），其余几百个地点只是孤立的点，看不出攻击指向。现在每个上图的来源地点（最多 800 个）都有飞向受保护资产的动画飞线，线宽与亮度随攻击次数变化、出发时间错开；涟漪仍只用于突出攻击最多的 60 个地点。
- **内部对外的飞线**：内网主机对外的攻击或异常连接（外连威胁情报地址、木马回连、周期性外连、攻击后回连、数据外传、对外扫描等）原先以发起的内网主机为主体记录，内网地址没有地理位置，地图上完全看不到。现在另外记录外部目标及其归属地（第一次出现时发起在线溯源，最多 500 个，7 天没有再出现的不再显示，随快照保存），地图上以紫色虚线从受保护资产飞向外部目标（三角形标注），点击可查看外部地址、攻击类型与发起的内网主机，并直达相关告警；正常的出站访问不画线。图例与统计中增加“内部对外”。演示环境给演示情报中的外连目标配置了示意位置。
- **登录页动态背景**：浏览器报告“减少动态效果”时（Windows Server、远程桌面会话默认关闭系统动画）登录页只绘制一帧静态画面，看起来像动画消失了。现在这种情况下按舒缓模式播放（自转减半、轨迹更少，闪烁类动画仍关闭）；页面右上角增加“动效”开关，可明确开启完整动画或关闭，选择保存在浏览器中。

### 修复

- **页面上的乱码（同类问题统一处理）**：除攻击目标外，告警证据、User-Agent、攻击源标签说明、X-Forwarded-For、资产攻击链路的步骤证据与对端、攻击面发现的证据、原始日志检索结果、数据源“最近一条无法解析的日志”、归档库历史告警的证据与 User-Agent 都会把日志中的控制字符与非法字节原样显示为方块或问号。现在写入时统一转义为 `\xHH`（C 字符串末尾的 NUL 去掉），载入快照时整理旧数据，原始日志导出保持原样用于取证；页面的转义函数对残留的控制字符同样按 `\xHH` 显示。原始日志检索截断长日志时不再删除其中的非法字节（改为按字符边界截断、转义显示）。
- **截断出半个字符**：自学习的请求形态示例、诱饵命中说明、自学习的目标统计键、进程命令行、单点登录的账号名在按字节截断时会把中文等多字节字符截成半个，显示为 `�`。现在统一按字符边界截断。
- **攻击目标中的乱码**：扫描器把 TLS、RDP、DNS、SMB 等二进制协议发往 HTTP 端口时，nginx 把收到的字节当作请求行记录，旧版本把这串原始字节直接当作攻击目标（站点 + 请求行），攻击活动、攻击源、事件、资产攻击链路的“主要目标”里出现大段乱码；每个随机的二进制载荷还各占一个目标名额，挤掉真正的目标。现在这类请求按协议显示为“站点（非 HTTP 请求：TLS 握手 / RDP / DNS 查询（TCP） / SMB / Flash 策略文件请求 / SQL Server 预登录 / Redis 命令 …）”，识别不出协议的二进制统一记为“二进制数据”并合并计数；正常请求 URI 中的控制字符转义显示。升级后载入快照时自动整理已保存的目标，归档库中的历史告警在查询时同样整理。
- 非 HTTP 协议探测告警的证据按字节转义：随机字节恰好构成合法 UTF-8 时（如 `\xd5\xa1`）不再显示成零散的怪字。

## 1.11.2

### 修复

- **停用的观察规则仍计入攻击源评分与总览排行**：纠错回溯只修正了事件，攻击源的评分、等级和总览的高频规则、攻击类型排行仍按停用规则的命中计算。生产环境中员工出口地址 101.231.58.190 的 36,911 次攻击里有 36,901 次来自被业务轮询停用的观察规则，一直显示为高危攻击源；总览的高频规则第一名也是这条规则（41,994 次，占全部攻击的近一半）。现在停用的观察规则不再计入攻击源的评分与等级（等级分布随之更新），也不进入高频规则与攻击类型排行；原始命中保留在攻击次数等总量统计和攻击源详情中，规则重新启用后恢复计入。升级后启动时自动生效。
- **回溯与恢复可能乱序**：停用观察规则与重新启用分别在独立的协程里通知状态库，先后顺序没有保证，停用后随即重新启用时可能先恢复、后回溯，规则已启用而告警停留在已撤销的状态。现在按发生顺序依次执行。
- **华为告警日志计为解析失败**：设备告警（trap）以日志形式发出时没有 `%%` 前缀、消息以 OID 开头（如 `CONFIG/4/CONFIGCHANGE:OID 1.3.6.1.4.1.2011...` 配置变更），此前计为解析失败并触发“日志格式可能已变更”的判断。现在与其他运维日志一样计为跳过；带中文地址字段（源IP地址=、目的地址=）却解析失败的行仍计为失败。
- 聚合接口的响应缓存在统计代码出现异常（panic）时没有释放条目锁，之后该接口同样参数的请求会全部挂起，直到重启。现在异常只影响当次请求。

### 性能

- **syslog 报文头解析提速约 4 倍**：每条 syslog 日志都要先剥离报文头，原先的正则以 `(.*)$` 捕获正文，引擎要逐字节扫描整条日志（华为会话日志每条约 8.7µs）。现在只匹配报文头、按位置截取正文，并按 PRI 之后的首字符跳过不可能匹配的格式，每条约 2.2µs，结果与原实现逐条一致（新增对照测试）。生产环境每天数千万条防火墙日志，接收端 CPU 占用相应下降。
- Cisco ASA 解析器先按字面量定位 `%ASA-` / `%FTD-` 消息头，其他格式的日志不再进入正则匹配：带大量 `%XX` 编码的 Web 请求上快约 38 倍（自动识别格式时每条日志都会经过它）。nginx 解析器的快速路径失败后，不含 `] "` 的行（防火墙、syslog 等）同样不再进入正则匹配。6 万条畸形日志的健壮性测试由 45~84 秒降到约 26 秒，解析结果不变。

### 修复

- **自学习把员工的业务接口学成“未知攻击”**：员工出口地址的几条误报（长连接重连、浏览器插件探测 `/.git/HEAD`、验证码预检）让模型以 85%～95% 的置信度把它们判为攻击源，自动确认后，它们每隔几秒轮询的心跳接口 `GET /uaa/api/ht/sid` 被学成观察规则，所有命中再升一级，生产环境一天多出上千条中危告警。现在：

### 修复

- **防火墙管理服务对公网放行**：华为 / H3C 的策略匹配日志（`POLICYPERMIT`）只说明策略放行，没有会话与应答。默认策略放行了公网到设备自身（local 安全域）时，扫描器探测的每个端口都会记一条“放行”，此前在每个公网地址上报出 NETCONF、HTTP 管理等一串并不存在的服务（生产环境 31 条）。现在：
  - 有证据表明端口上有服务在应答（会话有应答，或同一来源连接 10 次以上）时，才按端口记“防火墙管理服务对公网放行”；
  - 否则按策略合并记一条“防火墙策略放行公网访问设备自身”：默认策略 `default` 为高危，其余中危。这才是需要处置的配置问题；
  - 快照恢复时撤销旧版本只凭单次探测记下的记录。
- **流量洪泛**：打向 Web 端口的连接，九成以上被放行且服务端正常应答、或该来源同时出现在 Web 日志中（策略匹配日志没有应答信息）时不判为洪泛：NAT 后面的大量用户、页面不断重连的长连接都会这样，是不是攻击由 Web 日志的 CC 检测判断；没有应答的大量连接（SYN 洪泛）照常判定。旧版本记录的这类洪泛在资产攻击链路中按需核实处理（生产环境中 60.2.41.105 让 10.34.44.88 推进到了“影响”）。
- **CC 攻击**：内网来源的高频请求（未还原真实地址的反向代理、监控、内部扫描器）从高危改为低危的弱证据。
- **管理后台识别**：`console` 只认第一、二级目录（`/console`、`/nacos/console`），业务接口里带这个词的路径（`/app/api/console/push-messages`）不再当成管理后台；快照恢复时按新规则重新核对已登记的入口。
- **安全评估**：
  - Web 防护的拦截率只统计外部来源，内部漏洞扫描器不经过边界的 WAF，计入会把拦截率拉到接近 0（已保存的历史计数无法区分来源，随新的流量逐步恢复）；
  - 暴露面的结论按类型说明（高危服务、敏感资源、管理后台），只有确实存在敏感数据可下载或严重 / 高危服务时才写“无需利用漏洞即可获取”；
  - 边界防护的结论按服务归并（`Rsync(873) ×3 台`），不再重复列出同一服务。

### 改进

- **登记授权扫描**：资产攻击链路提示“越过侦察的攻击都来自内网地址”时，攻击来源中的内网地址旁可直接点“登记为授权扫描”，跳到事件处置页并预填扫描源与说明。
- **性能**：Web 路径归一不再为每条日志分配切片；日志时间解析先试上一次成功的格式、只试同一类格式。端到端处理每批的内存分配次数减少约 37%，分配量减少约 26%。

### 加固

- **流量设备白名单**（`flow.allowlist`）：开启后只接收 `flow.exporters` 中登记的设备，其余来源的数据包直接丢弃（计为跳过）；UDP 源地址可以伪造，建议开启。每台设备最多保存 256 个模板，总数满时淘汰最久没有更新的，伪造的大量模板挤不掉正常设备的模板；设备上报的采样率记录数同样有上限。

### 改进

- **长连接按时长折算**：会话 / 流记录了持续时间时（Zeek `duration`、NetFlow / IPFIX 的起止时间、FortiGate `duration`、Palo Alto 会话时长），结束时一次性报告的字节数、包数按时长平均折算到统计窗口；持续两小时的备份、一小时的同步不再被当成外传或带宽型 DDoS 的突发。Palo Alto TRAFFIC 日志同时解析包数。
- **安全评估**：“日志与检测覆盖”增加“已接入主机进程日志（EDR / HIDS）”与“已部署诱饵”两项检查（各项权重重新分配，合计仍为 100）。
- 资产攻击链路各阶段的说明补充 P3 的证据（Web 进程执行命令、载荷下载、反弹 Shell、恶意 TLS 指纹、凭证窃取、带宽型 DDoS 等）；告警查询的来源筛选增加“主机进程日志”。
- CI 的测试步骤失败时，把失败用例、断言行、panic 与第一个数据竞争报告写成注解，不登录也能在运行页面看到原因。

### 数据窃取（P2-1）

### CC 与 DDoS 检测

- **分布式 CC**（`bhv-distcc`，高危）：按站点汇总，请求量比平时暴增 5 倍以上（且不少于 `dist_cc_requests`），一半以上集中在同一路径，且有 `dist_cc_ips` 个以上来源各集中请求该路径 `dist_cc_ip_requests` 次以上。单个来源都低于 `cc_requests` 时，按来源统计发现不了这类攻击。正常的访问高峰（访客请求各种页面）与 App 低频轮询不会告警。

### Tengine、OpenResty 与 nginx 系网关的日志

- **Tengine、OpenResty、Kong** 的访问日志与 nginx 相同，照常识别；自定义 `log_format` 支持 Tengine 的 `$request_time_msec`、`$request_time_usec` 与 `$unix_time`，以及 `$remote_port`。

### 检测规则

- **nginx alias 目录穿越**：`/static../etc/passwd` 这样以 `..` 结尾的路径段此前被当作普通目录名放过，现在按目录穿越告警。

- **Nginx UI**：签名库新增未授权下载备份（CVE-2026-27944）、MCP 接口（CVE-2026-33032）、安装接口（CVE-2026-42221）。签名共 261 条，规则共 81 条。

- 新增 **APISIX**（`ip-restriction` 全局规则）与 **Kong**（`ip-restriction` 全局插件）导出格式；nginx deny 格式同样适用于 Tengine、OpenResty 与 Nginx UI。

### 误报（来自生产环境）

- **高速扫描被判为高危的“流量洪泛/DoS”**：来源 5 分钟内对上百个地址的随机端口各连一次，事件数超过阈值就判为洪泛，占了高危告警的近四成。现在分散到大量端口或主机的连接只按端口扫描告警，集中打向少数目标的才是洪泛。
- **App 过期令牌被判为“Web登录暴力破解”**：只统计登录类接口与 HTTP Basic 认证（`$remote_user`）的 401，业务接口因会话过期返回的 401 不再计入。
- **二进制协议探测被判为高危的“空字节截断”**：TLS 握手、Oracle TNS 等发往 HTTP 端口的请求只判为协议探测（低危），Oracle TNS 单独注明。
- **pdf.js 预览本站文件被判为“远程文件包含”并列为疑似失陷**：参数中的地址属于本站（同一主域名）时不告警。
- **扫描开头的探测被记为“疑似攻击成功”**：兜底页面被认出后，同站点、同响应大小的疑似成功记录随即撤销。
- **事件标为误报或忽略时撤销疑似成功**：同时撤销该来源名下没有证据的“疑似攻击成功”，不再列为疑似失陷资产（有证据的保留）。升级前已误记的，把对应来源的事件标为误报即可清除。
- **周期性外连**：定时 ping 外部地址判为低危；多台内网主机以同样规律连接同一地址（统一部署的代理）时，之后的主机判为低危。
- **华为、H3C 设备的运维日志**（命令记录、接口状态等）计为跳过，不再算作解析失败；带地址字段却解析失败的行仍算失败。

- **态势研判条**与上方指标卡按同样的 8 列对齐、高度一致，近 1 小时攻击的环比放到数字右侧。
- **实时告警**中连续出现的同名低危告警（互联网背景的端口扫描）合并为一条，显示次数与来源数。
- **攻击拦截率**按数值着色：低于 40% 为黄色提示，此前一律为绿色。
- 指标卡标签、副文本与实时告警的字号调大一号。

### 国产 OA、中间件漏洞接口签名

- 内置 254 条签名，覆盖致远、泛微、用友、通达、蓝凌、万户、金和、宏景、红帆 OA，帆软、Smartbi、亿赛通、畅捷通 T+、若依、JeecgBoot、Nacos、XXL-JOB、ThinkPHP、织梦、骑士等，以及深信服、天融信、奇安信、锐捷、H3C、海康威视、大华等共 41 个国产产品。由 `tools/vulnpaths` 从 nuclei-templates（MIT 许可）提取，另有少量人工补充。
- 请求带有注入、穿越、命令执行等载荷时判为“已知漏洞利用”，名称注明产品与 CVE / CNVD 编号；只访问了漏洞接口（载荷在请求体里、或用 GET 确认接口是否存在）时判为“漏洞接口探测”，中危。

### 威胁情报

- **域名情报**：情报源中的域名（文本列表、hosts 文件格式、URL、STIX `domain-name` / `url`、MISP `domain` / `hostname` / `url`）与 DNS 日志中内网主机的查询比对，上级域名同样命中。情报源常把被滥用的公共平台本身列进来（`raw.githubusercontent.com`、网盘、CDN），这类条目、内网后缀与 `intel.domain_allowlist` 中本单位的域名一律丢弃。
- **情报类别**（`kind`：`c2` / `malware` / `phishing` / `mining` / `attacker`）：决定命中的分类与等级。远控名单维持原有的失陷判定；扫描、暴力破解来源的名单只说明信誉，外部来源访问最高中危，不再单独构成高危；矿池按挖矿处置，钓鱼按钓鱼网站提示。
- **情报源准确率学习**：事件记录命中过的情报源，分析员处置后按情报源统计确认攻击与误报；长期误报的情报源，只由它产生的情报命中自动下调一级（有其他准确的情报源同时标记时不下调），可在“自学习”页面锁定。
- **认证请求头**：`token_header` 指定密钥放在哪个请求头（abuse.ch 的 `Auth-Key`、AbuseIPDB 的 `Key`）。
- **docker 部署默认启用免费情报**：Feodo Tracker 远控地址与 Spamhaus DROP（只作信誉提示）。隔离网络把 `intel.feeds` 改为 `[]`。

### 自学习

- **业务接口学习**：存在已知漏洞、但站点正常业务在用的接口（如致远 OA 的 `htmlofficeservlet`），被 8 个以上网段、此前没有攻击记录的访客正常访问后认定为业务接口，只访问接口、没有载荷的请求降为低危；能看到载荷的照常告警。结果在“自学习”页面列出。

### 误报（行为变化）

- **跑着致远、万户、通达 OA 的站点，正常访问被判为高危**：原有“中间件/OA系统漏洞利用”规则把整个 `/yyoa/`、`/defaultroot/` 目录，以及 `/seeyon/webmail.do`、`/ispirit/interface`、`/general/login_code.php` 这类正常业务接口都按高危告警。这部分已移除，改由签名库判断；只访问 `htmlofficeservlet`、`bsh.servlet.BshServlet` 这类接口、看不到载荷的请求现在是中危（此前高危）。

## 1.7.7

### 检测

- **libinjection 语法分析**：查询参数中的 SQL 注入、XSS 命中再按 SQL 词法、HTML 解析复核，构成注入的在证据中注明；规则没有命中、语法分析认定为 SQL 注入的生成“SQL注入（语法分析）”，补上 `1' div 0 --`、`1)) or ((1`、`admin' or 1#` 这类正则漏掉的变形。只看含有引号、括号、注释的参数，正常请求的检测耗时基本不变。
- **部分规则改编自 OWASP CRS**：对比了 Coraza + CRS v4.25（偏执等级 1：内置样本检出 72.8%、正常样本告警 12%、每条约 1ms），只看日志时误报偏高、慢约 300 倍，不整体引入；把本引擎缺的命令注入（awk、sed、base64、crontab、Windows FOR 循环、PowerShell 下载执行）、PHP 危险函数与变量函数调用、Java 危险类名、Node.js 注入、PostgreSQL 类型转换注入、localhost 的各种写法改写成 10 条原生规则。内置规则 69 → 79 条，CRS 回归样本的检出从 410 条提高到 585 条。
- **防火墙与 Web 日志联动**：Web 攻击之后，内网主机连接攻击载荷中写明的回连地址判为严重（载荷已被执行），对外提供服务的主机连接攻击者判为高危，其他主机中危；攻击前就连接过的地址、本单位自己的公网地址、公共 DNS 不关联。高危以上列为疑似失陷主机，并自动确认攻击源。

### 自学习

- **参数的正常取值**：按站点、接口、参数统计正常访客的取值形态。注入命中落在平时就填写普通文字的参数里、且语法分析判定不构成注入时降为低危（搜索“select 用法 from 入门教程”）；平时只出现数字的参数出现引号、括号时生成低危的“参数取值偏离正常形态”。
- **被动识别站点产品**：从正常访问中识别每个站点使用的产品与开发语言（WordPress、PHP、Java、致远 / 泛微 / 用友 OA、Nacos、WebLogic……）。针对站点上从未出现过的产品的漏洞探测、请求也没有成功时降为低危。同时按文件名识别前端框架与库（Vue、React、Angular、jQuery、Bootstrap、layui、Element、iView 等，文件名里带版本号的一并记下），以及能从路径看出来的 Node.js 后端（Socket.IO、Next.js、Nuxt、SvelteKit、对外暴露的 webpack 开发服务器）。
- 两项都要两个独立依据同时成立才降级，只降到低危、仍然生成告警；学习需要来自 20 个以上网段的正常访问，结果在“自学习”页面展示。

### 修复

- **DNS 带外探测被封顶为高危**：内网主机解析 DNSLog 等带外平台域名本应是严重，但分类名与定级表不一致，被按“没有证据”封顶成了高危。“账号异常”“动态域名/内网穿透”的分类底线同样补齐，并增加测试保证检测产生的每个分类都在定级表中。
- **定时外连任意外部地址的 443 端口被当成内部调用**（1.7.6 引入）：docker 部署默认把 80、443 作为兜底端口视为已发布，判断“是否连接本单位自己的服务”时也算了进去，导致 C2 心跳常用的 443 端口只打标签。现在只认清单中写明了公网地址的映射和由会话证据识别的对外服务。

## 1.7.6

### 从日志与 AI 研判中自动学习攻击行为

学到的东西只让检测更敏感，不降低任何告警的等级，所以不需要人工确认、自动生效；结果在“自学习”页面展示并记入审计链。

- **自动确认攻击源**：有证据的成功利用、模型以 85% 以上置信度判为攻击的来源，有效期内（默认 30 天）复现时低危 / 中危命中升一级，最高高危。分析员之后判为误报的以分析员为准。
- **攻击活动关联**：攻击载荷中带外回连标识（interactsh、dnslog 等）相同的来源关联为同一攻击活动，其中有已确认攻击源时其他来源一并确认。
- **未知攻击发现**：只出现在已确认攻击源、没有命中任何规则、正常访客从未使用的请求形态，被 3 个以上攻击源使用后生成低危观察规则，可在页面停用。

### 误报

- **定时外连不再列为疑似失陷主机**：只凭固定间隔的外连（中危）、或只连过 Tor 出口，不足以判定失陷——定时调用接口、监控探活、软件更新同样规律。命中威胁情报、安全设备报出恶意软件等高危迹象才列为疑似失陷；规律外连仍告警并在攻击面中提示。
- **定时连接本单位自己对外发布的服务**（如内部调用模型接口）不再按 C2 心跳告警，只打标签。

## 1.7.5

- **docker 部署默认开启对外发布服务清单**（`configs/docker.yaml` 的 `exposure.enabled: true`）：打到没有在防火墙上映射的公网端口的探测与端口暴力破解只打标签，不告警、不计入威胁评分；已映射端口、经 DNAT 转发到内网的访问与 Web 应用上的攻击照常告警。对外服务由会话证据自动识别，80、443 作为兜底端口视为已映射。不需要时把 `enabled` 改为 `false`。

## 1.7.4

基于真实的防火墙与 nginx 日志排查发现并修复：

### 误报与定级（行为变化）

- **扫描器打单页应用刷出成片高危、严重**：攻击请求的响应与站点首页一样大，说明路径不存在、返回的是兜底页面，载荷没有到达应用，最高中危（此前高危）。与接口正常响应一样大、或只是多个探测路径大小相同的仍按高危封顶。
- **攻击源被评为严重**：扫描器把各类漏洞载荷都试一遍、全部没有成功时，按类型累加的评分会顶到 100。攻击源达到严重现在必须出现过严重告警或失陷迹象。
- **几千个“疑似失陷资产”**：旧版本只凭 2xx 就把攻击成功记为严重，这些历史记录现在按高危显示；同一资产命中多种“成功”只有至少一条带证据时才算高置信。攻击面发现满 5000 条后淘汰最久没出现的，不再丢弃新发现。
- **内网主机被当成境外攻击源、应用连数据库被判为暴力破解**：使用 172.168.0.0/16 这类非 RFC1918 地址的内网，防火墙日志里来源安全域为 trust、dmz 等内部区域时按内部来源处理；内部来源被放行的连接不按连接次数判定暴力破解，被拒绝的照常统计。
- **nginx 日志站点名错误、请求耗时缺失**：combined 格式之后的 `$request_time`、`$host` 现在会识别；经 syslog 转发时 syslog 标签不再被当成站点名。

### 新增检测

- **慢请求 / 超时攻击**（`timeout_window`、`timeout_requests`、`slow_request`）：同一来源持续收到 504 / 408 或请求耗时过长，且明显多于同站其他访客。
- **疑似破坏性攻击**：此前正常的业务路径在可疑来源（超时攻击、攻击后写操作成功）活动后对多个访客失效。

### 自学习

- **从原始日志自动学习内网网段**：同一 /24 网段作为内部安全域的来源出现 20 次后认定为内网，已有攻击源的归属地随之更正，记入进化日志与审计链，不需要人工结论。

### 性能

- **态势评估、攻击面页面卡顿**：疑似失陷资产、攻击面发现有几千条时全部返回并渲染（真实数据下主线程卡住 1.7 秒，每 15 秒刷新一次）。接口只返回排在前面的 200 / 300 条并给出总数，页面最多渲染 100 行。

## 1.7.3

### 浏览器卡顿、无响应

- **开多个标签页后所有页面卡住**：每个标签页都占一条实时告警长连接，HTTP 访问时浏览器对同一站点最多 6 条连接，开到第 6 个标签页后所有请求排队。实时告警只显示在态势总览页，现在只在该页可见时保持连接。通过 HTTPS 访问（HTTP/2）没有这个限制。
- **放一会再操作时卡死**：离开态势总览页后，实时告警仍在累积地图闪点，没有上限，回到总览页时一次性绘制，几千个时页面无响应。现在不再累积。
- **离开总览页后地图仍在后台绘制**：飞线和涟漪动画隐藏后每秒仍有数万次绘制，现在离开时停止，回来时恢复原来的缩放位置；持续动画的攻击源最多 60 个，其余显示为静态点；IP 详情中的小地图关闭后释放。
- **定时刷新不再叠加**：上一轮没有返回时跳过这一轮；告警列表内容没有变化时不重建表格。

### 原始日志检索

- **分页**：默认每页 100 条，可选 50 / 100 / 200 / 500。此前最多显示最新的 500 条，一次攻击产生大量日志时后面的看不到。
- **超长行**：单行超过 4KB 的只显示开头，导出仍是完整内容。
- **断电后日志检索不到**：进程被强制结束或断电时，正在写入的分段末尾只写了一半，之后写入的日志都检索不到。现在跳过损坏部分继续读取，升级后之前受影响的日志也能查到。

- **严重需要响应码之外的证据**。只有 2xx 响应的“疑似成功”最高高危；未拦截的盲打类攻击（Log4j、SSRF 等）同样最高高危。自定义规则如果把上述分类写成严重，也按此处理。证据种类见[严重需要的证据](detection.md#威胁等级判定)。
- 升级时，待处理事件中只凭响应码判为严重的（失陷迹象类除外）调整为高危并写入处置记录，出现有证据的告警时自动升回；已关闭的事件不变。
- 没有证据的 Web 攻击不再计入高置信失陷，按中置信统计。

### 检测

- 响应与站点首页相同、或与多个探测路径大小相同（单页应用、统一错误页）时，注入、穿越、命令执行也判为未成功，之前只覆盖敏感文件和 WebShell。
- 响应明显大于接口基线时判为有证据的成功；接口基线随快照保存，重启后不需要重新学习。
- 降低误报：路径中的普通相对引用（`/assets/../assets/app.js`）不再判为目录穿越；只出现在普通文字里的特征（搜索“<script> 标签的用法”）最高低危；兜底页面上的 WebShell 探测修正为中危。
- 减少漏报：识别 `%c0%af` 等超长 UTF-8 编码绕过、`PROCEDURE ANALYSE()`、`AND (SELECT ...)`。

### AI 研判

- 只有 2xx 响应的事件现在可以被模型高置信下调，下调和恢复都以有无证据为准。
- 自动研判可选择包含中危事件，严重的事件优先。
- 事件列表支持批量加入研判队列，用于重新研判升级前的事件。
- 发给模型的信息区分“疑似成功”和“有证据”。
