## 1.7.0

### 对接外部系统（新增，默认关闭，见[对接外部系统](integrations.md)）

- **单点登录**：LDAP / Active Directory、OpenID Connect；按组映射角色。
- **SIEM 转发**：syslog（UDP / TCP / TLS），CEF、JSON、RFC 5424。
- **联动封禁**：申请、审批、到期解除；防火墙拉取名单或 Webhook 推送；内网和保护名单不能封禁。
- **工单与处置剧本**：事件满足条件时自动指派、写入处置步骤、创建工单、提交封禁申请。
- **在线情报**：STIX、TAXII 2.1、MISP、文本列表；过滤内网地址和过宽的网段，防止情报投毒。
- **规则运营**：页面维护规则并热更新、样本试运行、Sigma 导入、ed25519 签名规则包。

### 可靠性与安全

- **处置记录不丢**：每次修改先写预写日志并落盘，`kill -9` 或断电后重放。
- **备份恢复**：`netsa backup` / `restore`、定时备份、页面下载；恢复前校验每个文件的 SHA-256。
- **容器加固**：`docker-compose.yml` 默认去掉全部 Linux 能力、禁止提权、只读根文件系统、限制内存和进程数。如果你在容器内写了状态卷以外的目录，升级后需要改为挂载卷。
- **发布链路**：镜像漏洞扫描、SBOM。
- **测试**：权限矩阵覆盖全部路由；前端 E2E 与 XSS 回归；CI 接入 PostgreSQL 集成测试。

### 定级（行为变化）

- **严重需要响应码之外的证据**。只有 2xx 响应的“疑似成功”最高高危；未拦截的盲打类攻击（Log4j、SSRF 等）同样最高高危。自定义规则如果把上述分类写成严重，也按此处理。证据种类见[严重需要的证据](detection.md#威胁等级判定)。
- 升级时，待处理事件中只凭响应码判为严重的（失陷迹象类除外）调整为高危并写入处置记录，出现有证据的告警时自动升回；已关闭的事件不变。
- 没有证据的 Web 攻击不再计入高置信失陷，按中置信统计。

### 检测

- 响应与站点首页相同、或与多个探测路径大小相同（单页应用、统一错误页）时，注入、穿越、命令执行也判为未成功，之前只覆盖敏感文件和 WebShell。
- 响应明显大于接口基线时判为有证据的成功；接口基线随快照保存，重启后不需要重新学习。
- 降低误报：路径中的普通相对引用（`/assets/../assets/app.js`）不再判为目录穿越；只出现在普通文字里的特征（搜索“<script> 标签的用法”）最高低危；兜底页面上的 WebShell 探测修正为中危。
- 减少漏报：识别 `%c0%af` 等超长 UTF-8 编码绕过、`PROCEDURE ANALYSE()`、`AND (SELECT ...)`。

### AI 研判

- 只有 2xx 响应的事件现在可以被模型高置信下调，下调和恢复都以有无证据为准。
- 自动研判可选择包含中危事件，严重的事件优先。
- 事件列表支持批量加入研判队列，用于重新研判升级前的事件。
- 发给模型的信息区分“疑似成功”和“有证据”。

### 评测

- 新增 `netsa eval`：用带标注的样本跑完整检测流水线，输出检出率与误报；门槛接入测试，指标下降时 CI 失败。内置样本是手工构造的回归基线，不代表真实流量的准确率。

### 其他

- 升级 `golang.org/x/sys`，修复 GO-2026-5024（代码未调用到）。新增依赖 `go-ldap`。
- 新增[安全策略](../.github/SECURITY.md)和本文件；采用 [Apache License 2.0](../LICENSE)。
