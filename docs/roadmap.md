# 能力评估与路线图

[← 返回 README](../README.md)

按攻击链路逐段评估识别、定位、溯源三方面的能力，列出缺口与分步计划。评估基于真实生产环境的数据：日均约千万条防火墙日志、数十万条 Web 日志，期间有一次完整的 nuclei 扫描与持续的互联网背景扫描。状态随版本更新。

## 三、分步计划

### P0（1.7.11，已完成）

生产环境的 nuclei 扫描中只有 22% 的请求被识别。已补齐：兜底页面上的目录扫描、整段漏洞扫描识别与工具识别、OAST / DNSLog 回连域名、备份与配置文件的大量变体、以站点名命名的源码包、随机名脚本、编码绕过。回放这次扫描中漏掉的 300 个请求，新版本按单条请求识别 41%，其余由来源级的扫描识别归并。

### P1（1.7.12 ~ 1.8.0，已完成）

1. **攻击活动归并**（1.7.12 首版，1.8.0 补充 OAST 关联标识）：同一工具指纹、同网段且手法相似、同一云厂商的地址轮换扫描同一主机、载荷中同一 interactsh 关联 ID / dnslog 子域名的地址归为同一攻击活动，列出成员、来源网段、关联依据与建议封禁网段。验收：同 ASN 轮换扫描的地址归为一个活动；同一 nuclei 任务（同一关联 ID）的多个出口地址归为一个活动（`TestCampaigns`、`TestCampaignsOAST`）。
2. **资产攻击链路**（1.8.0）：以站点 / 主机 / 台账资产为中心，侦察、利用、突破、植入、控制、横向、窃取、影响按时间串起，每一步注明证据、来源与 ATT&CK 技术；站点与背后的服务器按台账、Web 日志记录的服务器地址、回连地址合并；失陷研判、IP 详情可直接展开。验收：演示数据经完整流水线（各日志并发读取）后，官网与服务器 10.0.0.10 合并为一条链路，完整展示“扫描 → 漏洞利用 → 命令注入成功 → 回连 → 横向 → 窃取”（`TestDemoAssetChain`）。
3. **编码载荷还原**（1.8.0）：路径段与参数中的 Base64、Hex，以及路径中用 `+` 代替空格的注入解码后再过规则（`%uXXXX`、HTML 实体此前已还原）；只采信能单独说明攻击的分类，SQL 注入与 XSS 须语法分析确认。验收：Base64 / Hex 编码的穿越、命令执行、表达式注入载荷被识别，JWT、回跳网址等正常写法不误报（`TestDecodedPayloads`、内置评测 `encoded` 组）；正常请求的检测耗时增加约 2%，绝大多数请求都带长令牌的极端情况约 5%（`BenchmarkDecodeTypical`、`BenchmarkDecodeOverhead`）。
4. **防火墙攻击防范日志**（1.8.0）：华为 ANTIATTACK / IPS、H3C ATK / IPS、深信服 DOS / IPS / WAF 日志解析为设备威胁；只记录目的地址的洪泛日志按目的地址告警；设备的洪泛判定与按会话日志判断的多源 DDoS 相互印证。验收：按厂商公开字段说明构造的样例（`TestAttackDefense`、`TestDeviceFloodCorroboration`）。**待办**：拿到现场设备的真实日志后核对字段名、分隔符与分类，补充到测试样例。
5. **授权扫描登记**（1.8.0）：事件处置 → 授权扫描登记，登记扫描源、起止时间与说明，期间只记录不告警、不计入攻击统计、评分、资产攻击链路与自学习，期间的命中按登记汇总。验收：登记期间的扫描不产生告警，时间窗之外、未登记的来源照常告警，过期后自动恢复检测（`TestAuthorizedScan`、`TestMatchWindow`）。

### P2（1.9.0，已完成）

1. **数据窃取**：按内网主机统计外发字节的基线，突增告警（`bhv-exfil`）；Web 侧按来源统计下载量突增（`bhv-download`）。验收：与基线相比暴增为高危，没有基线时按阈值的 4 倍判断，图片与视频不计入（`TestExfil`、`TestDownloadSurge`）；演示数据中失陷服务器的外传出现在资产攻击链路的“窃取”阶段。
2. **WebShell 行为画像**（`bhv-webshell`）：新出现的脚本路径、只被极少来源访问、以 POST 为主、响应 / 请求大小随请求变化，并与此前的上传请求关联。验收：上传后访问新脚本的来源判为有证据；多个来源访问的页面、观察期内的脚本、以 GET 为主的不告警（`TestWebShellBehavior`）。
3. **横向移动**：被攻击的服务器事后第一次发起的内网管理连接（`bhv-lateral-new`）、东西向管理协议的扇出（`bhv-lateral-fanout`）、Windows 4624 类型 3 / 10 的横向登录链（`auth-lateral-chain`）。验收：攻击之前就有的连接、跳板机的固定路径、间隔过久的两次登录不告警（`TestLateralMovement`、`TestLogonChain`）；演示数据中失陷服务器的内网连接出现在“横向”阶段。
4. **一键取证包**：导出事件详情、时间线、来源画像、资产攻击链路、归档告警、原始日志与 SHA-256 哈希清单（`TestIncidentEvidence`）。
5. **日志增强**：解析 `$request_length`、`$upstream_status`、`$upstream_response_time`、`$ssl_protocol`、`$ssl_cipher`（及网关的 JA3 / JA4），用于成功研判、WebShell 画像与客户端指纹；同源关联增加 TLS 指纹与行为节奏两条线索（`TestEnhancedFields`、`TestUpstreamReview`、`TestCorrelateTLSAndRhythm`）。

### P3（1.10.0，已完成）

1. **流量级数据源**：Zeek `conn` / `http` / `ssl` / `files`（TSV 带表头或 JSON）、NetFlow v5 / v9、IPFIX、sFlow v5 采集（按采样率还原字节数与包数，窗口内合并）、云抗 D 服务的攻击事件。覆盖：请求体（`post_body` 与 nginx `$request_body` 参与规则匹配）、TLS 指纹（JA3 / JA4 与 SNI 按情报匹配）、带宽型 DDoS（按目的地址的入向流量基线，`bhv-ddos-bw`）、传输的文件（哈希情报、攻击之后下载的载荷）。验收：按协议格式构造的数据包（含截断与随机损坏）解码不越界，采样率按选项模板 / 样本 / 配置还原（`TestNetFlowV5`、`TestNetFlowV9`、`TestIPFIX`、`TestSFlow`、`TestFlowCollector`）；Zeek 四类日志（`TestZeekLogs`）、抗 D 事件（`TestCloudDDoS`）；NTP 反射按目的地址告警一次、平时流量大的地址按自己的基线判断（`TestBandwidthDDoS`）。
2. **诱饵**：诱饵路径、诱饵线索、诱饵账号、蜜罐地址（含 OpenCanary 日志），页面与配置文件维护；命中即高置信攻击者（自动确认来源），使用同一线索 / 账号的地址互相关联并归入同一攻击活动。验收：各类诱饵命中、正常请求不命中、重复访问不重复告警、页面登记的诱饵与命中记录重启后保留（`TestDeception`）；两个出口地址使用同一诱饵线索后在同源关联中列为强关联（`TestP3Pipeline`）。
3. **EDR / HIDS 进程日志与应用登录日志**：Sysmon（1 / 3 / 10 / 11 / 12~14）、Windows 4688、ECS、auditd、Wazuh；Web 服务进程执行命令、WebShell 落地、反弹 Shell、编码 PowerShell、LOLBin、凭证窃取、持久化、痕迹清除与删除卷影副本，计入失陷研判与资产攻击链路；应用登录日志的不可能的旅行、首次从新的国家登录、多地并发登录（账号盗用）。验收：`TestProcessDetection`、`TestAppLogin`、`TestAccountTakeover`；完整流水线中载荷落地、IIS 执行命令、TLS 指纹命中的主机列为疑似失陷（`TestP3Pipeline`）。

### 后续

路线图列出的 P0 ~ P3 计划已全部完成。仍需在现场持续完善的：

- **厂商日志字段核对**：防火墙攻击防范日志（P1-4）与云抗 D 服务的攻击事件按公开文档整理，接入真实日志后核对字段名与分类，补充到测试样例；
- **未知攻击**（◐）：参数正常取值画像、攻击行为自学习与外部模型研判只能覆盖一部分，持续用现场的漏报样本补充规则与评测语料；
- **只有访问日志的站点**看不到 POST 请求体，建议接入 WAF 判定、记录 `$request_body` 或部署 Zeek。
