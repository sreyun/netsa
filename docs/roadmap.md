# 能力评估与路线图

[← 返回 README](../README.md)

按攻击链路逐段评估识别、定位、溯源三方面的能力，列出缺口与分步计划。评估基于真实生产环境的数据：日均约千万条防火墙日志、数十万条 Web 日志，期间有一次完整的 nuclei 扫描与持续的互联网背景扫描。状态随版本更新。

## 三、分步计划

### P0（1.7.11，已完成）

生产环境的 nuclei 扫描中只有 22% 的请求被识别。已补齐：兜底页面上的目录扫描、整段漏洞扫描识别与工具识别、OAST / DNSLog 回连域名、备份与配置文件的大量变体、以站点名命名的源码包、随机名脚本、编码绕过。回放这次扫描中漏掉的 300 个请求，新版本按单条请求识别 41%，其余由来源级的扫描识别归并。

### P1（下一阶段，按顺序）

1. **攻击活动归并**：把多个地址归为同一次攻击活动。依据：同一 OAST 关联标识（如 nuclei 的 interactsh 子域名前缀）、同一工具特征、同一 /24 网段或 ASN 在同一时间窗内打同一目标、相同的路径字典。页面列出活动的成员地址、时间线、涉及资产与整体处置建议（按网段封禁）。验收：分布式的互联网扫描（数十个同 ASN 地址轮换）归为一个活动；同一 nuclei 任务的多出口地址归为一个活动。
2. **资产攻击链路**：以站点 / 主机为中心，把侦察、利用、成功研判、回连、横向、窃取按时间串起，每一步注明证据、来源与 ATT&CK 技术；疑似失陷资产可直接展开链路。验收：演示数据中“扫描 → 漏洞利用 → 成功 → 回连”的资产能完整展示。
3. **编码载荷还原**：路径段与参数中的 Base64、Hex、`%uXXXX`、HTML 实体，以及路径中用 `+` 代替空格的注入，解码后再过规则；限定长度与字符集，控制性能开销。验收：Base64 编码的穿越 / 命令执行载荷被识别；正常请求的检测耗时增加不超过 5%。
4. **防火墙攻击防范日志**：华为、H3C、深信服的 ANTI-DDOS、ATK、IPS 日志解析为设备威胁，DDoS 类判定与多源 DDoS 检测互相印证。验收：用真实样例日志验证字段与分类。
5. **授权扫描登记**：页面登记授权扫描源（地址或网段、起止时间、说明），期间只记录不告警、不计入攻击统计与评分。验收：登记期间的扫描不产生告警，过期后自动恢复检测。

### P2

1. **数据窃取**：按内网主机统计外发字节与会话数的基线，突增告警；Web 侧按来源统计下载量突增。
2. **WebShell 行为画像**：新出现的脚本路径、只被极少来源访问、以 POST 为主、响应大小随请求变化，并与此前的上传请求关联。
3. **横向移动**：被攻击的 Web 服务器事后发起的内网连接；Windows 4624 类型 3 / 10 的横向登录链；SMB、RDP、WinRM 的东西向异常。
4. **一键取证包**：导出事件相关的原始日志（附哈希）、时间线、研判依据与处置记录。
5. **日志增强**：建议 nginx 增加 `$request_length`、`$upstream_status`、`$upstream_response_time`、`$ssl_protocol`、`$ssl_cipher`，解析后用于成功研判与客户端指纹。

### P3

1. 流量级数据源：Zeek（conn、http、ssl、files）、NetFlow / sFlow、云厂商抗 D 日志，覆盖请求体、TLS 指纹与带宽型 DDoS。
2. 诱饵：诱饵路径、诱饵账号、蜜罐，命中即高置信攻击者，并关联其全部地址。
3. EDR / HIDS 进程日志与应用登录日志，补齐主机侧执行、持久化与账号盗用的证据。
