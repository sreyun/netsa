# 自学习与 AI 研判

[← 返回 README](../README.md)

平台如何从分析员的处置结论中持续学习，以及可选的外部大模型研判。

“系统配置 → 自学习”页面集中展示以下能力。自学习策略在“规则准确率与自动校准 → 策略”中调整（管理员，初始值见 `learn:`）；外部模型在“外部模型 → 配置模型”中配置（管理员）。

**哪些学习结果会自动生效**：分析员的结论积累到阈值后，校准与升级会自动作用于之后的检测，无需重启或人工操作；会隐藏告警的误报抑制始终需要人工采纳。

| 学习结果 | 是否自动生效 | 作用 |
|---|---|---|
| 规则级校准 | 自动 | 准确率持续偏低的规则，命中等级下调一级 |
| 目标级精细校准 | 自动 | 只在个别目标上反复误报的规则，只下调该目标上的命中 |
| 确认攻击源复现升级 | 自动 | 被确认为攻击的来源再次出现，低危 / 中危命中升级一级 |
| 威胁情报源准确率 | 自动 | 命中某个情报源的事件反复被判为误报，只由它产生的情报命中下调一级 |
| 内网网段自动识别 | 自动 | 防火墙日志中同一 /24 网段作为内部安全域（trust、dmz 等）的来源出现 20 次后认定为内网，不再按境外地址定位、按内部来源处理放行的连接 |
| 业务路径与接口响应基线 | 自动 | 学习站点首页与各接口的正常响应，判断攻击请求拿到的是不是兜底页面，以及业务路径何时失效 |
| 自动确认攻击源 | 自动 | 有证据的成功利用、模型以 85% 以上置信度判为攻击的来源，有效期内复现时低危 / 中危命中升一级（最高高危） |
| 攻击活动关联 | 自动 | 载荷中带外回连标识相同的来源关联为同一攻击活动；其中有已确认攻击源时，其他来源一并确认 |
| 未知攻击发现 | 自动，可停用 | 只出现在已确认攻击源、没有命中任何规则、正常访客从未使用的请求形态，生成低危观察规则 |
| 参数的正常取值 | 自动 | 注入命中落在平时就填写普通文字的参数里、且语法分析不构成注入时降为低危；平时只出现数字的参数出现注入符号时提示（见下方[参数的正常取值与站点产品](#参数的正常取值与站点产品)） |
| 站点产品识别 | 自动 | 站点从未出现过攻击针对的产品、请求也没有成功时降为低危 |
| 业务接口学习 | 自动 | 存在已知漏洞、但站点正常业务在用的接口，只访问接口、没有载荷的请求降为低危 |
| 攻击后回连 | 自动 | 防火墙日志中被攻击的内网主机连接攻击者或载荷中的回连地址，自动确认该攻击源（见[检测说明](detection.md#防火墙与-web-日志联动被攻击后回连)） |
| 对外服务自动识别 | 自动 | 有会话证据的对外服务计入攻击面（见[未做 DNAT 映射的端口探测](log-sources.md#未做-dnat-映射的端口探测)） |
| 误报抑制建议 | 人工采纳 | 采纳后符合条件的命中不再告警 |
| 外部模型一致率 | 仅评估 | 写在 AI 研判记录中，帮助判断模型结论的可信度 |
| 可信模型的误报判断 | 人工采纳 | 一致率高的模型多次判为误报的“规则 + 目标”形成待确认建议，不会自动生效 |
| 模型适配信息 | 自动 | 记住模型不支持的参数与输出上限，之后不再出错（见下方“模型适配”） |

页面顶部的“自动生效”统计本次启动以来被自动下调 / 升级的命中次数，监控指标为 `netsa_learn_applied_total{kind="rule|target|escalate"}`。

- **从原始日志自动学习**（不需要人工结论）：只学日志本身能证明、学错了也不会把攻击藏起来的内容。
  - **内网网段**：企业把 172.168.0.0/16 这类已分配为公网的地址段用在内网时，只看地址会把内部主机定位到境外、把应用服务器连数据库判为暴力破解。防火墙日志里的安全域说明了报文从哪一侧进来，同一 /24 网段作为内部安全域的来源出现 20 次后自动认定为内网，已有攻击源的归属地随之更正。依据记入进化日志与审计链，页面“日志自动学习”可以看到学到了哪些网段。被拒绝的访问照常告警。
  - **响应基线**：站点首页、各接口的正常响应大小，用于判断攻击是否真的成功（与首页一样大说明拿到的是兜底页面）。
  - **业务路径可用性**：此前正常服务多个访客的路径，用于发现业务受损（见检测说明中的“疑似破坏性攻击”）。
- **从日志与 AI 研判中学习攻击行为**（不需要人工结论）：学到的东西只让检测更敏感，不降低任何告警的等级，学错的代价是多几条告警而不是漏掉攻击，所以自动生效。“自学习”页面的“从日志与 AI 自动学到的攻击行为”列出全部结果，每一项都记入进化日志与审计链。
  - **自动确认攻击源**：出现有证据的成功利用（响应码之外的第二份证据）、攻击之后被攻击的服务器回连了该来源，或模型以 85% 以上的置信度把事件判为攻击时，自动确认来源。有效期与“确认攻击源复现升级”相同（默认 30 天，从最近一次证据算起），期间该来源的低危 / 中危命中升一级，最高高危；关闭该策略时不生效。分析员之后把该来源判为误报的，以分析员为准。
  - **攻击活动关联**：从攻击载荷中提取带外回连标识（interactsh 子域名的前 20 位关联 ID、dnslog / ceye 等的子域名）。同一标识出现在多个来源上，说明是同一个操作者用多个 IP 扫描；其中有已确认的攻击源时，其他来源一并确认。只看命中攻击规则的请求。
  - **未知攻击发现**：已确认攻击源发出、没有命中任何规则的请求，按请求形态归类（方法、去掉数字与长 ID 的路径、参数名，不含参数值）。同一形态被 3 个以上已确认攻击源使用、而其他来源从未使用时，生成观察规则：之后任何来源使用这个形态都按低危提示（分类“未知攻击（自学习）”），管理员可在页面停用。静态资源和首页不参与；记录每种形态被哪些正常来源用过（内存有上限）。
- **研判反馈学习**：从分析员的处置结论中学习，已处置计为确认攻击，误报计为误报。会降低告警等级的校准只基于人的结论：模型和系统自动生成的状态不参与，避免模型的错误判断把真实攻击降级。
  - **规则级校准**：研判样本不少于 5 个、且准确率不高于 20% 的规则，等级自动下调一级；管理员可锁定规则，立即恢复原等级。
  - **目标级精细校准**：规则整体准确率正常、只在个别目标上反复误报时（同一规则在同一目标上被研判为误报不少于 3 次、且从未确认为攻击；目标按“主机 + 路径”归一，忽略查询参数），只下调该目标上的命中一级，其他目标不受影响。该目标上出现确认的攻击、或锁定规则后自动恢复。
  - **下调的边界**：一次命中最多下调一级，最多低于攻击分类底线一级（如 SQL 注入从高危降到中危，不再推送、处置时限按中危）；有证据证明利用成功时仍升为严重（只有 2xx 响应不算，校准照常生效）。若仍按底线抬回，注入、命令执行这类底线即高危的规则，校准就完全不起作用。
  - **确认攻击源复现升级**：事件被处置为“已处置”（确认攻击）的来源，在 30 天内再次出现时，其低危 / 中危攻击命中升级一级（最多到高危，严重只能来自成功利用等证据），证据中注明原事件编号。只看来源最近一次结论：同一来源后来被判为误报（如确认是授权扫描）就不再升级。有效期按日志时间计算，离线分析历史日志时同样准确。
  - **威胁情报源准确率**：情报不在多而在准。事件会记录命中过哪些情报源（入站来源、内网主机连接的地址、解析的域名）。
    - 分析员处置后，按情报源统计确认攻击与误报的次数；误报不要求事件只涉及少数规则，被判为误报的来源说明情报把正常来源标记成了恶意。
    - 样本不少于 5 个、准确率不高于 20% 的情报源（与规则校准使用同一策略），之后只由它产生的情报命中下调一级。有其他准确的情报源同时标记时不下调，仍然生成告警。
    - 准确率回升、样本过期或在“自学习 → 威胁情报源准确率”中锁定后自动恢复。Tor 出口节点是事实性的名单，不参与统计。
  - 同一规则在同一目标上多次误报，或同一来源多次被整体判为误报（疑似授权扫描），会生成抑制建议，由人工采纳。
  - **学习窗口**：只用最近 180 天的结论（可在策略中调整，0 表示不限）。业务变化后，旧结论自动失效，相应的校准自动撤销，避免早年的误报结论一直压低新的告警。
  - **进化效果**：页面按周统计人工结论中的误报占比，持续下降说明检测在变准。
  - 每次自动调整与策略修改都写入进化日志和审计链。
  - 批量处置（最多 500 个事件）的结论一次计入，学习状态只重算、保存一次。
- **平台行为基线**：学习每个账号的常用登录网段与时段，以下情况会推送告警并写入审计链：
  - 从新地址登录；在非常用时段登录；
  - 登录失败暴增；1 小时内导出 5 次以上；
  - 关闭双因素认证、新增或提升管理员、创建管理员令牌、添加范围过宽的误报抑制、关闭 syslog 发送端白名单、修改外部模型的地址或关闭发送前脱敏。
- **持续合规自检**：每小时自动执行一次等保检查，任何一项结果下降都会告警，并保留 30 天的符合率趋势。每天凌晨自动校验审计链完整性。
- **外部大模型（可选，默认关闭）**：同时支持 **OpenAI 兼容接口**（`/chat/completions`）与 **Anthropic 接口**（`/messages`），适用于内网部署的 vLLM、Ollama，以及 DeepSeek、通义千问、智谱、Kimi 等云端模型。
  - **在 Web 管理页面配置**：管理员在“自学习 → 外部模型 → 配置模型”中选择接口协议，填写模型地址、模型名称、模型密钥并勾选启用；可点“获取模型列表”选择准确的名称，再“测试连接”；保存后立即生效，无需重启。另可设置每小时调用上限、思考模式、输出长度上限、调用超时、发送前脱敏与高危事件自动研判。
  - **密钥保护**：密钥只保存在服务端状态目录的 `ai.json`（文件权限 0600），任何接口与页面都不回显（只显示末 4 位用于核对）；修改时留空表示保持原值。模型地址换到其他主机时必须重新填写密钥，防止密钥被发往新地址。配置变更与连接测试都写入审计链（不含密钥）。
  - **兼容原有配置**：界面从未保存过时沿用配置文件 `ai:` 段，升级无需改动；在界面保存后以界面配置为准。
  - 在事件详情中点击“AI 研判”触发；开启自动研判后，新出现的高危及以上事件会自动研判（严重优先，每分钟最多 3 个），可选择把范围扩大到中危。在事件列表勾选事件后点“AI 研判”可以批量加入后台队列（最多 500 个），用于重新研判升级前的事件；同样受每小时调用上限约束。连接公网的模型服务必须使用 HTTPS。
  - 发送前默认脱敏：内网地址（IPv4 与 IPv6 ULA / 链路本地）、口令和令牌、手机号、证件号、邮箱。
  - 每小时有调用次数上限，每次调用都写入审计链。
  - **与自学习联动**：研判时附带本单位的历史人工结论（同一来源、同一规则在同一目标上的确认 / 误报次数）和最相关的相似案例（分析员的处置说明、被分析员纠正过的模型判断），让模型吸取本环境的经验。模型结论仍不作为学习样本，而是在分析员处置后与其结论比对，统计每个模型的一致率、漏判（把确认的攻击判为误报）与误判次数。评估满 5 个事件后，AI 研判记录中会附上该模型的一致率。
  - **可信模型的建议**：评估满 10 个事件且一致率不低于 80% 的模型，以不低于 80% 的置信度把同一规则 + 目标判为误报 3 次以上、分析员尚未处置、且该目标从未确认过攻击时，生成“模型判断”的抑制建议，由人工采纳。
  - **高置信误报自动降级**（默认开启，可在模型配置中关闭）：模型以不低于 85% 的置信度判为误报时，事件等级下调一级、处置时限随之放宽，事件保持待处理，等分析员确认。送给模型的日志可能被攻击者控制，因此有以下边界：有证据证明成功或有失陷迹象、已是严重、涉及核心资产的事件不下调（只有 2xx 响应的疑似成功可以下调，这正是需要模型判断的情况）；已评估满 5 个事件且一致率低于 60% 的模型不下调；之后出现有证据的成功利用、失陷迹象或比下调前更高的等级时自动恢复；事件详情中可一键撤销。
  - 结论写入事件的处置记录，模型不会关闭事件，结论也不作为学习样本。

## 参数的正常取值与站点产品

参照 naxsi 的学习模式，但不需要人工整理白名单：从正常流量中自动学习，结果在“自学习”页面的“从正常流量学到的参数取值与站点产品”中展示。

**参数的正常取值**：按“站点 + 路径形态（数字、长 ID 归一）+ 参数名”统计正常请求中取值的形态（数字、编号、单个词、普通文字、JSON）。

| 情况 | 处理 |
|---|---|
| SQL 注入 / XSS 规则命中在平时就填写普通文字的参数里（至少 5% 的正常取值是普通文字），且语法分析判定不构成注入 | 按普通文字处理，最高低危，证据中写明依据 |
| 只有语法分析认定、没有命中注入规则的 SQL 注入（`sqli-syntax`），出现在这类参数里 | 同上（引号、括号多的普通文字） |
| 平时只出现数字、编号、单个词的参数（从未出现过注入符号），出现了引号、括号、尖括号等 | 没有命中规则时生成低危的“参数取值偏离正常形态”；命中规则时在证据中注明 |

**站点产品识别**：从正常访客成功访问（2xx / 304）的路径中识别每个站点使用的产品与开发语言，例如 `/wp-content/` 说明是 WordPress，`.php` 说明有 PHP，`.do`、`.action` 说明是 Java 应用，另外识别致远、泛微、用友、通达、蓝凌 OA、帆软、Nacos、Spring Boot、WebLogic、Exchange 等常见产品。

同时按脚本、样式的文件名识别前端框架与常用库：Vue（Vite 编译的 `*.vue_vue_type_*.js`、vue-cli 的 `chunk-vendors.*.js`）、React（create-react-app 的 `/static/js/*.chunk.js`）、Angular、AngularJS、UmiJS、jQuery、Bootstrap、layui、Element、iView；文件名或 CDN 目录里带版本号的（`jquery-1.8.3.min.js`、`/jquery/3.5.1/jquery.min.js`）一并记下，便于排查过旧的前端库。Node.js 后端只有出现 `/socket.io/`、Next.js 的 `/_next/`、Nuxt 的 `/_nuxt/`、SvelteKit 的 `/_app/immutable/`、对外暴露的 webpack 开发服务器（`/sockjs-node/`、`/__webpack_hmr`）时才能认出：日志里没有 `X-Powered-By` 这类响应头，只提供接口的 Node 服务看不出来。`sockjs.min.js` 是浏览器端的库，常配 Java 后端，不作为 Node.js 的依据。前端框架只用于展示，不参与漏洞适用性判断。针对特定产品的漏洞利用（ThinkPHP、WebLogic、Exchange、Confluence、F5、GPON 路由器……）、按脚本后缀访问的 WebShell 与敏感文件探测，在站点上从未出现过该产品或开发语言、请求本身也没有成功（404、被拦截、出错）时，攻击不可能得手，最高按低危处置。

**业务接口学习**：存在已知漏洞的接口也可能是正常业务在用，例如致远 OA 的 `htmlofficeservlet` 就是正文编辑插件的接口，见[国产 OA、中间件漏洞接口签名](detection.md#国产-oa中间件漏洞接口签名)。同时满足以下条件的访问计入：
- 站点有足够多的正常访问；
- 请求只命中了漏洞接口签名，没有任何攻击载荷；
- 响应为 2xx / 3xx；
- 访客此前没有任何攻击记录（扫描器通常先打过别的探测，不计入）。

同一接口被 8 个以上网段的这类访客访问过，就认定为业务接口，之后此前没有攻击记录的访客只访问接口、没有载荷的请求降为低危；扫描器、已确认攻击源的探测仍按中危（扫描器在真实的 OA 站点上找到了存在漏洞的接口，这个信号不能压低），能看到载荷的照常按已知漏洞利用告警。不要求先识别出产品：不少产品没有专属目录，否则这些产品的站点上正常业务会一直按中危告警。已认定的接口随学习状态保存，在“自学习”页面列出。

**边界**：

- 只降到低危，仍然生成告警，不隐藏；有证据的成功利用、已确认攻击源的请求不降级；成功的请求不做产品判断。
- 都要两个相互独立的依据同时成立：参数平时就是普通文字 + 语法分析不构成注入；站点没有该产品 + 请求没有成功。单凭任何一个都不降。
- 防投毒：只用没有命中攻击规则、来源不是已确认攻击源的请求学习；同一网段（IPv4 /24、IPv6 /48）的来源只算一个。参数要有 200 次以上正常取值、来自 20 个以上网段；站点要有 300 次以上正常访问、来自 20 个以上网段；某个产品至少被 3 个网段的正常访客访问过才算出现过。访问量小的站点不做判断。
- 内存有上限：最多统计 2 万个参数（满了淘汰最久没出现的）、2000 个站点、5000 个漏洞接口；已生效的结果随学习状态保存，30 天没再出现的自动清理。
- 页面顶部统计本次启动以来按普通文字降级、发现取值异常、判为产品不适用、业务接口降级的次数。
- 签名覆盖的国产产品如果有专属目录（`/seeyon/`、`/defaultroot/`、`/cdgserver3/`、`/webreport/` 等），正常访问中出现时同样识别为站点产品。

## 模型适配

不同模型和部署方式的行为差异很大，平台按模型（协议 + 主机 + 模型名）自动适配，无需逐项配置。“外部模型”面板显示研判成功率、平均耗时与已学到的适配项。

| 情况 | 平台的处理 |
|---|---|
| 推理模型（Qwen3、DeepSeek-R1 等） | 自动请求关闭思考（vLLM 的 `chat_template_kwargs.enable_thinking=false`，Qwen3 在参数不可用时追加 `/no_think`）；观察到思考过程后也会对该模型启用。可在“思考模式”中改为始终关闭或保留 |
| 思考过程混在正文中 | 去掉 `<think>` 段（包括只有结束标签的情况），也识别 `reasoning_content` 字段与 Anthropic 的 thinking 内容块；思考过程里的花括号、草稿不影响提取结论 |
| 输出被截断 | 输出长度上限加倍重试一次；仍被截断时说明原因 |
| 回复不是 JSON | 请模型把回复转换为 JSON；结论字段的常见变体（中文结论、`"85%"`、`0.85`、单个字符串的依据）都能识别 |
| JSON 模式下返回空内容 | 关闭 `response_format` 重试，并记住 |
| 参数被拒绝（400 / 422） | 从错误信息学习并记住：`max_tokens` 超过上下文或输出上限时计算可用值、改用 `max_completion_tokens`、不再发送 `temperature` / `response_format` / `chat_template_kwargs` |
| Anthropic 接口拒绝 `x-api-key`（401） | 改用 `Authorization: Bearer` 并记住，适配网关和 vLLM |
| 限流、网关错误、连接失败（429 / 502 / 503 / 504） | 等待后重试一次 |
| 模型拒绝回答（`refusal`、`content_filter`） | 说明原因，不重试；安全事件内容可能触发云端模型的内容策略，内网模型不受此影响 |
| 协议选错、模型名称不存在 | “测试连接”自动尝试另一种协议；模型不存在时列出接口提供的模型 |
| 粘贴了完整地址、只填了主机 | 自动去掉 `/chat/completions`、`/messages`，只有主机时补 `/v1` |

一次研判最多调用模型 3 次（均占用每小时额度）。没有得到结论时，处置记录写明原因和模型输出的节选，不计入模型的一致率。
