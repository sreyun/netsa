# 自学习与 AI 研判

[← 返回 README](../README.md)

平台如何从分析员的处置结论中持续学习，以及可选的外部大模型研判。

“系统配置 → 自学习”页面集中展示以下能力。自学习策略在“规则准确率与自动校准 → 策略”中调整（管理员，初始值见 `learn:`）；外部模型在“外部模型 → 配置模型”中配置（管理员）。

**哪些学习结果会自动生效**：分析员的结论积累到阈值后，校准与升级会自动作用于之后的检测，无需重启或人工操作；会隐藏告警的误报抑制始终需要人工采纳。

| 学习结果 | 是否自动生效 | 作用 |
|---|---|---|
| 规则级校准 | 自动 | 准确率持续偏低的规则，命中等级下调一级 |
| 目标级精细校准 | 自动 | 只在个别目标上反复误报的规则，只下调该目标上的命中 |
| 确认攻击源复现升级 | 自动 | 被确认为攻击的来源再次出现，低危 / 中危命中升级一级 |
| 对外服务自动识别 | 自动 | 有会话证据的对外服务计入攻击面（见[未做 DNAT 映射的端口探测](log-sources.md#未做-dnat-映射的端口探测)） |
| 误报抑制建议 | 人工采纳 | 采纳后符合条件的命中不再告警 |
| 外部模型一致率 | 仅评估 | 写在 AI 研判记录中，帮助判断模型结论的可信度 |
| 可信模型的误报判断 | 人工采纳 | 一致率高的模型多次判为误报的“规则 + 目标”形成待确认建议，不会自动生效 |
| 模型适配信息 | 自动 | 记住模型不支持的参数与输出上限，之后不再出错（见下方“模型适配”） |

页面顶部的“自动生效”统计本次启动以来被自动下调 / 升级的命中次数，监控指标为 `netsa_learn_applied_total{kind="rule|target|escalate"}`。

- **研判反馈学习**：只从分析员的处置结论中学习，已处置计为确认攻击，误报计为误报。
  - **规则级校准**：研判样本不少于 5 个、且准确率不高于 20% 的规则，等级自动下调一级；管理员可锁定规则，立即恢复原等级。
  - **目标级精细校准**：规则整体准确率正常、只在个别目标上反复误报时（同一规则在同一目标上被研判为误报不少于 3 次、且从未确认为攻击；目标按“主机 + 路径”归一，忽略查询参数），只下调该目标上的命中一级，其他目标不受影响。该目标上出现确认的攻击、或锁定规则后自动恢复。
  - **下调的边界**：一次命中最多下调一级，最多低于攻击分类底线一级（如 SQL 注入从高危降到中危，不再推送、处置时限按中危）；响应证明利用成功时仍升为严重。若仍按底线抬回，注入、命令执行这类底线即高危的规则，校准就完全不起作用。
  - **确认攻击源复现升级**：事件被处置为“已处置”（确认攻击）的来源，在 30 天内再次出现时，其低危 / 中危攻击命中升级一级（最多到高危，严重只能来自成功利用等证据），证据中注明原事件编号。只看来源最近一次结论：同一来源后来被判为误报（如确认是授权扫描）就不再升级。有效期按日志时间计算，离线分析历史日志时同样准确。
  - 同一规则在同一目标上多次误报，或同一来源多次被整体判为误报（疑似授权扫描），会生成抑制建议，由人工采纳。
  - **学习窗口**：只用最近 180 天的结论（可在策略中调整，0 表示不限）。业务变化后，旧结论自动失效，相应的校准自动撤销，避免早年的误报结论一直压低新的告警。
  - **进化效果**：页面按周统计人工结论中的误报占比，持续下降说明检测在变准。
  - 每次自动调整与策略修改都写入进化日志和审计链。
  - 批量处置（最多 500 个事件）的结论一次计入，学习状态只重算、保存一次。
- **平台行为基线**：学习每个账号的常用登录网段与时段，以下情况会推送告警并写入审计链：
  - 从新地址登录；在非常用时段登录；
  - 登录失败暴增；1 小时内导出 5 次以上；
  - 关闭双因素认证、新增或提升管理员、创建管理员令牌、添加范围过宽的误报抑制、关闭 syslog 发送端白名单、修改外部模型的地址或关闭发送前脱敏。
- **持续合规自检**：每小时自动执行一次等保检查，任何一项结果下降都会告警，并保留 30 天的符合率趋势。每天凌晨自动校验审计链完整性。
- **外部大模型（可选，默认关闭）**：同时支持 **OpenAI 兼容接口**（`/chat/completions`）与 **Anthropic 接口**（`/messages`），适用于内网部署的 vLLM、Ollama，以及 DeepSeek、通义千问、智谱、Kimi 等云端模型。
  - **在 Web 管理页面配置**：管理员在“自学习 → 外部模型 → 配置模型”中选择接口协议，填写模型地址、模型名称、模型密钥并勾选启用；可点“获取模型列表”选择准确的名称，再“测试连接”；保存后立即生效，无需重启。另可设置每小时调用上限、思考模式、输出长度上限、调用超时、发送前脱敏与高危事件自动研判。
  - **密钥保护**：密钥只保存在服务端状态目录的 `ai.json`（文件权限 0600），任何接口与页面都不回显（只显示末 4 位用于核对）；修改时留空表示保持原值。模型地址换到其他主机时必须重新填写密钥，防止密钥被发往新地址。配置变更与连接测试都写入审计链（不含密钥）。
  - **兼容原有配置**：界面从未保存过时沿用配置文件 `ai:` 段，升级无需改动；在界面保存后以界面配置为准。
  - 在事件详情中点击“AI 研判”触发；开启自动研判后，新出现的高危及以上事件会自动研判。连接公网的模型服务必须使用 HTTPS。
  - 发送前默认脱敏：内网地址（IPv4 与 IPv6 ULA / 链路本地）、口令和令牌、手机号、证件号、邮箱。
  - 每小时有调用次数上限，每次调用都写入审计链。
  - **与自学习联动**：研判时附带本单位的历史人工结论（同一来源、同一规则在同一目标上的确认 / 误报次数）和最相关的相似案例（分析员的处置说明、被分析员纠正过的模型判断），让模型吸取本环境的经验。模型结论仍不作为学习样本，而是在分析员处置后与其结论比对，统计每个模型的一致率、漏判（把确认的攻击判为误报）与误判次数。评估满 5 个事件后，AI 研判记录中会附上该模型的一致率。
  - **可信模型的建议**：评估满 10 个事件且一致率不低于 80% 的模型，以不低于 80% 的置信度把同一规则 + 目标判为误报 3 次以上、分析员尚未处置、且该目标从未确认过攻击时，生成“模型判断”的抑制建议，由人工采纳。
  - **高置信误报自动降级**（默认开启，可在模型配置中关闭）：模型以不低于 85% 的置信度判为误报时，事件等级下调一级、处置时限随之放宽，事件保持待处理，等分析员确认。送给模型的日志可能被攻击者控制，因此有以下边界：有疑似成功或失陷迹象、已是严重、涉及核心资产的事件不下调；已评估满 5 个事件且一致率低于 60% 的模型不下调；之后出现成功利用、失陷迹象或比下调前更高的等级时自动恢复；事件详情中可一键撤销。
  - 结论写入事件的处置记录，模型不会关闭事件，结论也不作为学习样本。

## 模型适配

不同模型和部署方式的行为差异很大，平台按模型（协议 + 主机 + 模型名）自动适配，无需逐项配置。“外部模型”面板显示研判成功率、平均耗时与已学到的适配项。

| 情况 | 平台的处理 |
|---|---|
| 推理模型（Qwen3、DeepSeek-R1 等） | 自动请求关闭思考（vLLM 的 `chat_template_kwargs.enable_thinking=false`，Qwen3 在参数不可用时追加 `/no_think`）；观察到思考过程后也会对该模型启用。可在“思考模式”中改为始终关闭或保留 |
| 思考过程混在正文中 | 去掉 `<think>` 段（包括只有结束标签的情况），也识别 `reasoning_content` 字段与 Anthropic 的 thinking 内容块；思考过程里的花括号、草稿不影响提取结论 |
| 输出被截断 | 输出长度上限加倍重试一次；仍被截断时说明原因 |
| 回复不是 JSON | 请模型把回复转换为 JSON；结论字段的常见变体（中文结论、`"85%"`、`0.85`、单个字符串的依据）都能识别 |
| JSON 模式下返回空内容 | 关闭 `response_format` 重试，并记住 |
| 参数被拒绝（400 / 422） | 从错误信息学习并记住：`max_tokens` 超过上下文或输出上限时计算可用值、改用 `max_completion_tokens`、不再发送 `temperature` / `response_format` / `chat_template_kwargs` |
| Anthropic 接口拒绝 `x-api-key`（401） | 改用 `Authorization: Bearer` 并记住，适配网关和 vLLM |
| 限流、网关错误、连接失败（429 / 502 / 503 / 504） | 等待后重试一次 |
| 模型拒绝回答（`refusal`、`content_filter`） | 说明原因，不重试；安全事件内容可能触发云端模型的内容策略，内网模型不受此影响 |
| 协议选错、模型名称不存在 | “测试连接”自动尝试另一种协议；模型不存在时列出接口提供的模型 |
| 粘贴了完整地址、只填了主机 | 自动去掉 `/chat/completions`、`/messages`，只有主机时补 `/v1` |

一次研判最多调用模型 3 次（均占用每小时额度）。没有得到结论时，处置记录写明原因和模型输出的节选，不计入模型的一致率。
