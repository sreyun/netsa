# AI 使用统计

[← 返回 README](../README.md)

员工自行使用大量 AI 工具（对话助手、编程助手、模型接口、AI 搜索……），单位需要先知道“谁在用什么、用了多少、往境外传了多少数据”，才能制定和落实使用制度。netsa 用已经接入的日志统计这些信息，不需要新的采集端：“风险管理 → AI 使用”。

这是 AI 使用治理的第一阶段（看得见）：只统计与展示，不拦截、不告警，也不进入攻击检测、威胁评分、失陷研判与自学习。

## 数据来源

| 日志 | 能统计什么 | 说明 |
|---|---|---|
| DNS 查询日志（BIND、dnsmasq、CoreDNS、Windows DNS、Zeek dns.log 等） | 哪个终端解析了哪个 AI 服务的域名（查询次数）；DNS 拦截（NXDOMAIN / REFUSED）计为“被拦截的尝试” | 最容易接入。终端地址取日志中的查询来源，日志要来自离终端最近的 DNS 服务器，否则看到的都是转发服务器 |
| TLS 握手日志（Zeek ssl.log 的 SNI） | 终端与哪个 AI 服务建立了加密连接（连接次数）；握手没有建立计为“被拦截的尝试” | 不经过内网 DNS 的访问（浏览器内置的 DoH、手工改 hosts）也能看到 |
| 会话日志（Zeek conn.log、防火墙会话日志、NetFlow / IPFIX）的字节数 | 上传 / 下载量 | 按 SNI 确认的“终端 + 目的地址”归属，见下文。没有 TLS 握手日志时没有上传量 |
| Web / 流量日志的 Host（Zeek http.log 等） | 明文请求的次数与请求 / 响应大小 | AI 服务基本都用 HTTPS，明文请求很少 |

### 上传量怎么算

AI 服务大多部署在 Cloudflare、Azure 等共享地址上，同一个地址后面还有成千上万个其他网站，只按目的地址归属会把访问其他网站的流量也算进来。所以只认 TLS 握手（SNI）确认过的组合：

- 先按完整的连接四元组：Zeek 的 conn.log 与 ssl.log 是同一条连接，归属是精确的；
- 再按“终端 + 目的地址”：防火墙记录的源端口可能与流量探针看到的不同（NAT、不同设备），会话开始时间在该终端与这个地址最近几段握手的前后 30 分钟以内才归属，同一地址上的两个服务（如 chatgpt.com 与 api.openai.com）按时间分开；
- 比较用的是日志自身的时间，补读积压、离线分析时同样适用。补读大量积压日志时，如果会话日志先于握手日志处理（两份文件读取进度不同），这部分会话的字节统计不到；实时跟踪时握手总是先于会话结束，不受影响。

## 服务目录

内置目录收录了常见的境内外 AI 服务（ChatGPT、Claude、Gemini、Copilot、DeepSeek、Kimi、通义千问、文心一言、豆包、腾讯元宝、智谱清言，Cursor、GitHub Copilot、通义灵码、Trae 等编程助手，OpenAI、Anthropic、Gemini、Azure OpenAI、Bedrock、DashScope、火山方舟、千帆等模型接口，Hugging Face、ModelScope、Ollama 模型库等模型下载），按以下属性统计：

- **类别**：对话助手 / 编程助手 / 模型接口 / 图像视频 / 语音会议 / AI 搜索 / 写作办公 / 智能体 / 模型下载。“模型接口”是程序在调用，办公终端以外的服务器调用境外模型接口值得关注；“模型下载”说明有人在本地部署模型；
- **所在地**：境内 / 境外（境外服务的上传量单独统计，涉及数据出境）；
- **策略**：允许 / 受限 / 禁止，按单位的 AI 使用管理制度设定。当前版本只用于统计“使用了禁止类服务的终端数”。

域名按标签匹配：`openai.com` 匹配 `api.openai.com`，从完整域名逐级向上找，最具体的登记优先（`api.openai.com` 归 OpenAI API，`chatgpt.com` 归 ChatGPT，官网 `openai.com` 本身不算使用）。含一个 `*` 的写法按前后缀匹配，如 `bedrock-runtime.*.amazonaws.com`、`*-aiplatform.googleapis.com`。`google.com`、`aliyuncs.com`、`amazonaws.com` 这类主域名下大部分业务与 AI 无关，不能整体登记，要写具体的子域名。

**无法按域名区分的**：SaaS 产品里内嵌的 AI 功能（飞书、钉钉、WPS、Notion、Office 365 Copilot 等）与产品本身使用同一域名，不在目录中，需要用这些产品后台的审计日志。

在页面“服务目录”中可以设定策略、登记目录之外的服务（API 中转站、单位自建的模型网关）；配置文件 `ai_usage` 中的服务与策略同样生效，页面设定的策略优先。

## 发现目录之外的 AI 服务

- **疑似 AI 服务**：DNS 查询或 TLS 握手中出现 openai、chatgpt、gpt、claude、anthropic、deepseek、llm、ollama、aigc、chatglm、qwen 等特征词（按 `.` `-` `_` 分隔后的完整词或以它开头，`egypt` 里的 gpt 不算），或使用 `.ai` 顶级域名、又不在目录中的，按注册域名列出，附出现过的完整域名与终端数。常见的是 API 中转站与新出现的工具。确认后点“登记”加入目录（之后的访问计入统计），不相关的点“忽略”。最多列 2000 个注册域名，满了以后淘汰只有一个终端、超过一天没有再出现的条目（优先淘汰只因 `.ai` 顶级域名列出的），`.ai` 域名不会挤掉含特征词的条目。
- **AI 接口发现**：Web 或流量日志中出现大模型接口路径的站点：OpenAI 兼容接口（`/v1/chat/completions`、`/v1/embeddings`、`/v1/models` 等，含 `/compatible-mode/v1/chat/completions` 这类路径）、Anthropic（`/v1/messages`）、Gemini（`:generateContent`）、Dify 应用接口，以及 11434 端口上的 Ollama 接口。用于发现内网自建、没有登记的模型服务，以及对外提供的模型接口（列出外网来源数）。只记录存在的接口（2xx / 3xx、401 / 403、405、429），扫描器在各网站上探测 `/v1/models` 时的 404 不算。

## 使用者与部门

终端地址按资产台账显示使用者与部门：在“资产漏洞”中按部门登记办公网段（如 `10.1.10.0/24`，部门“研发部”）或终端，即可按部门汇总。地址到账号的映射（域控登录、VPN、DHCP、802.1X 日志）在后续版本中提供。

## 权限、导出与报表

- 统计是员工的上网行为：查看与导出需要运营分析员以上权限，导出记入操作审计；服务目录（策略、登记、删除）只允许管理员修改；
- “导出 CSV”按终端与服务导出当前范围的统计；
- 周报 / 月报附有 AI 使用摘要（终端数、服务排行、境外上传、禁止类服务的使用者数），不列出具体终端：报告会通过邮件发送给更多人。

统计按域名识别，看不到对话内容。监控员工的上网行为需要事先在单位制度中告知。

## 配置

```yaml
ai_usage:
  enabled: true            # 默认开启
  policies:                # 服务编号见“服务目录”
    openai-api: deny
    chatgpt: restrict
    deepseek: allow
  services:                # 新增服务，或按 id 覆盖内置服务（只替换填写了的字段）
    - name: 内部大模型网关
      category: api
      region: domestic
      policy: allow
      domains: ["llm.corp.example"]
  disable: []              # 停用的内置服务
  retention_days: 62       # 按天统计的保留天数（覆盖“上月”月报）
  max_records: 300000      # “天 × 终端 × 服务”的记录数上限（约 40 MB 内存），超过时先淘汰最早一天
  file: ""                 # 默认与 storage.snapshot 同目录的 aiuse.json.gz
```

状态（页面登记的服务与策略、按天的统计、疑似域名、AI 接口）有变化时最多每 5 分钟保存一次，退出时立即保存；离线分析（`netsa analyze`）不读写这份状态。

## 能力边界

- 看不到内容：没有 SSL 解密代理或企业 AI 网关时，只能知道谁、什么时候、用了哪个服务、传了多少，不知道传了什么；
- 会被绕过：DoH / DoT、ECH、QUIC、手机热点、翻墙或代理工具会让 DNS 与 SNI 失效。对策是强制使用内网 DNS、封禁公共 DoH，并结合终端的进程日志；
- 下一阶段计划：地址到账号的映射、禁止类服务使用与境外大量上传的告警、例外审批登记、防火墙应用识别（App-ID）与上网行为日志、终端进程归属（Sysmon 22）、按域名导出封禁清单，以及自建 AI 服务的暴露面与漏洞签名。
